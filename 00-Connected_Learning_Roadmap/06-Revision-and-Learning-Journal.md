## The purpose of this document

Use this file to track what you can retrieve from memory, what needs another pass, and what you learned from mistakes. Keep entries brief. This is a learning aid, not an administrative task.

## Revision system: remember what you learn

Do not rewrite the same notes repeatedly. Keep concise reference notes, then use questions and practical tasks to retrieve the information from memory.

### Revision checkpoints

After learning a topic, revisit it at roughly these intervals when possible:

- **First revisit:** the next time you study.
- **Second revisit:** after a few other sessions.
- **Third revisit:** about a week later, if your schedule allows.
- **Later revisit:** during the next module review or a mixed practice lab.

These are reminders, not deadlines. If an interval passes, simply revise the topic when you return.

### Use this recall template

For each topic, answer without looking at the notes:

1. What is it?
2. Why does it exist?
3. How does it work?
4. Where would I encounter it in a real network?
5. What commonly goes wrong?
6. How would I verify or troubleshoot it?
7. What related Python tool or script could help, if any?

### Module review checklist

At the end of each module:

- [ ] Explain the main concepts aloud without reading.
- [ ] Draw or interpret a small diagram.
- [ ] Complete a practical lab or coding exercise.
- [ ] Answer a mixed set of questions from earlier modules.
- [ ] Record the three topics that still feel least certain.
- [ ] Revisit only the weak areas before moving on.
